## REQUIRED TEST, FIRST (from #106 finding 2 — the guard that was unexercisable until now)
`routeRelay`'s one-hop check on `to` (router.ts, `to.includes(':')` → RELAY_REFUSED) has been unreachable behind two masks: nothing could address `alias:x` through a relay because no outbound peering existed. F2 lifts both masks — with `hasOutboundPeer` true and a real forwarder, a relay whose `to` is `alias:x` is the transitive-relay attempt that check exists to stop. F2 MUST ship a test that goes RED when that check is dropped — and the obvious form of that test is STILL MASKED — by a LATER check, not an earlier one (mechanism corrected by mesh-builder at the tree): the one-hop check on `to` is FIRST in routeRelay (router.ts:223), so `to = 'C:agent'` passes the original test on shipped code; but with the check DROPPED, the frame falls through to the to-exists lookup, `getAgentById('C:agent')` is null, and it is refused ANYWAY with the same RELAY_REFUSED bytes — the mutant survives because a later check refuses identically. General form, and it recurs for every guard whose refusal is deliberately indistinguishable from its neighbours': on a uniform-refusal endpoint, asserting "refused" proves nothing unless every OTHER check has been made to PASS on purpose, so that only the check under test can refuse (found by pre-registering the cold read; the sentence citing #106's lesson was the one repeating it). Correct form: at B, construct a LEGACY colon-id LOCAL agent at the DB layer (as the suite already does for #106's legacy tests) — say `legacy:node` — grant the inbound edge `A:bob → legacy:node`, and relay from A with `to = 'legacy:node'`. Now to-exists passes, ACL passes, and the one-hop rule on `to` is the ONLY refusal → RELAY_REFUSED, same bytes as every other refusal; the mutant dropping the `to` check delivers to the legacy agent → RED. Enumerate in the test's comment every check that runs before the one under test and say why each passes. This test is the first thing the PR body lists.
