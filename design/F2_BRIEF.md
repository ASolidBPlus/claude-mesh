## REQUIRED TEST, FIRST (from #106 finding 2 — the guard that was unexercisable until now)
`routeRelay`'s one-hop check on `to` (router.ts, `to.includes(':')` → RELAY_REFUSED) has been unreachable behind two masks: nothing could address `alias:x` through a relay because no outbound peering existed. F2 lifts both masks — with `hasOutboundPeer` true and a real forwarder, a relay whose `to` is `alias:x` is the transitive-relay attempt that check exists to stop. F2 MUST ship a test that goes RED when that check is dropped: two servers, peering A→B, relay from A carrying `to = 'C:agent'` at B → RELAY_REFUSED, same bytes as every other refusal; mutant dropping the `to` check → the relay would be forwarded (or reach `deliverOrQueue` for a nonexistent local id) — the test must distinguish that from an ACL refusal (grant the edge first, the #106 one-hop-on-`from` lesson). This test is the first thing the PR body lists.

## Scope — two PRs
### PR-F2a — `outbound_peers` + the admin API + `routeDirect`'s remote branch + `messages.failed_code` (§4, §5.3, §6)
1. 2. `hasOutboundPeer(db, alias)` gets its real body: an ENABLED `outbound_peers` row. The F1b positive control (`local → alias:x` without peering → NO_PEERING) stays; with a peering → written.
3. Admin API (§6): `POST /outbound-peers {alias, url, token, assigned_alias, kinds?, rate_per_min?}` — `url` must be `ws://`/`wss://` (loopback allowed); `alias` must satisfy `PEER_ALIAS_RE`, not `RESERVED_ALIAS`, and **an outbound alias that prefixes a legacy local id (`alias:` prefix of any existing `agents.id`) → 400** (§13) — the population `assertPeeringAllowed` classifies as local must never become addressable as remote; `DELETE /outbound-peers/:alias` — forwarder stopped AND, in the SAME transaction, every undelivered row to `alias:*` gets `expires_at = now` (§5.6, the only moment anyone knows those rows are undeliverable; a DOWN peering is different and untouched); `GET /outbound-peers` (alias, url, assigned_alias, kinds, rate_per_min, enabled, last_alive — never token); `PATCH /outbound-peers/:alias {enabled?, token?, url?, rate_per_min?}` — restarts the forwarder with the new credential WITHOUT expiring queued rows. Start/stop/restart is event-driven from these handlers, never polled. Handlers receive the `Map<alias, Forwarder>` positionally, the way `startHttpAdmin` receives `agentIndex` (state the parameter position in the PR).
4. `routeDirect` remote branch (§5.3), in this order, before the existing recipient lookup: `to` contains `:` → split at the FIRST `:`; prefix is an ENABLED outbound alias → remote path; else fall through to the local lookup UNCHANGED (legacy colon ids keep working; unknown alias → the same `AGENT_NOT_FOUND` as an unknown local id). Remote path: remainder must be bare (a second `:` → `AGENT_NOT_FOUND`, never a wasted relay) → `kind ∈ outbound kinds` else `KIND_NOT_ALLOWED` (the sender's own configuration, no cross-border oracle) → outbound `aclCheck(from_agent, to)` (fail → `AGENT_NOT_FOUND`) → #95's duplicate check in the SAME position as today (above the metrics, which are the first side effect — #96 pins it) → insert with `to_agent = frame.to`, `expires_at` from `ttl_ms` as today, EXCEPT `ttl_ms = 0`: relay immediately if the peering socket is connected, else drop with `ack` ("online" for a remote id = "peering connected") → **ack the local sender now** (D8) → `borderEvents.emit('enqueued', alias)` fire-and-forget. **Invariant, named and pinned:** `routeDirect` stays SYNCHRONOUS through the duplicate check and the insert; the emit is after the synchronous section and never awaited; two-concurrent-duplicates test on the remote branch whose async-before-insert mutant must fail. No `from_agent` refusal in `routeDirect` (C5; the WS identity cannot be forged; MCP is covered by `requireLocalSender`).
5. `failed_code`: set on a permanent `RELAY_REFUSED` from the peer, together with `expires_at = now`; `countPendingMessages` and the retention sweep's still-deliverable exclusion both treat a row with `failed_code` as not pending — state which queries change and pin each.

### PR-F2b — the border forwarder (`server/border.ts`) + `PeerClient` hardening (§5 "Border forwarder", §5.6, §13)
1. `server/border.ts`: one `Forwarder` per enabled `outbound_peers` row, started at boot and by the F2a handlers; uses `PeerClient` (import via the same relative path `router.ts` uses for the SDK; `border.ts` imports `db.ts`, never `router.ts`) with `agent_id = assigned_alias`, `protocol: 1`. Exports `borderEvents` (module-level EventEmitter; `router.ts` imports it).
2. Drain (§5): the range query on `to_agent` between `alias + ':'` and `alias + ';'` (index-served; `LIKE` was verified to full-scan) with `delivered_at IS NULL AND failed_code IS NULL AND (expires_at IS NULL OR expires_at >= now) AND sent_at >= now - RELAY_DEDUPE_MS ORDER BY sent_at LIMIT ?`, excluding an in-memory in-flight set; rows older than the dedupe window are expired (`expires_at = now`), not sent. A test asserts the query plan uses the `to_agent` index (EXPLAIN QUERY PLAN: `SEARCH … USING INDEX idx_messages_to_agent`, no `SCAN`; a `USE TEMP B-TREE FOR ORDER BY` is expected and NOT a failure — assert the absence of SCAN, not the absence of temp structures, or the test reds for a reason unrelated to the property; verified on a409141).
3. Pacing, sender-side (§5): token bucket per peering — sustained `rate_per_min`, burst `rate_per_min` — AND an in-flight cap of `min(50, rate_per_min / 4)`; send only when both allow. A `RATE_LIMITED` from the receiver halves the local refill until the next success. Each relay carries `ttl_ms = max(1, expires_at - now)` (omitted when `expires_at IS NULL`) — never 0 for a stored row.
4. Outcomes via `PeerClient.relay()`: ack → `markDelivered` (`delivered_at` set ONLY on the peer's ack); permanent `RELAY_REFUSED` → `failed_code` + `expires_at = now` and, if the originating agent is connected, one `{type:'error', code:'REMOTE_REFUSED', ref: row.id}` best-effort (D5); transient `RATE_LIMITED` / `ACK_TIMEOUT` / `CONNECTION_RESET` → row stays pending, leaves in-flight, backoff 1 s doubling to 60 s, reset on success. Drain triggers: connect/reconnect, `borderEvents` for the alias, 30 s backstop tick. `mesh_peer_up{alias}` reflects the forwarder's socket — and is emitted for EVERY configured outbound peer at 0 or 1, never only when connected (the inbound half's defect: a series that appears only once set cannot be alerted on; see #108 — if it has not landed, F2b fixes both halves in one shape); `mesh_peer_relays_total{alias,direction='outbound',outcome}`.
5. `PeerClient` hardening (§5.6 + #102): `AUTH_FAILED` is ALREADY fatal at any time in `PeerClient.isFatalError` (peer-client.ts:52, verified on fd503c1 — `MeshClient`'s default only treats it as fatal before first auth); F2b PINS it at the forwarder level (a receiver-side revocation → the forwarder sets `enabled = 0` with a logged reason and the reconnect count stays 0 over a window — the test is about the forwarder's reaction, the client half exists); `subscribe`/`unsubscribe` throw locally with a clear message (closes #102), positive control that `MeshClient` still subscribes.
7. ONE authority for the protocol version: export `PEER_PROTOCOL_VERSION` from `client/src/protocol.ts` (a runtime constant beside the types); `PeerClient.authExtras()` returns `{protocol: PEER_PROTOCOL_VERSION}`; `server/ws-server.ts` imports it by the same relative path the forwarder uses for the SDK and deletes its own copy. Test: a mutant changing the exported constant changes BOTH what a peer announces and what the server accepts (they still agree); a mutant re-introducing a literal on either side is the thing this item exists to prevent — say so in the comment at the export. Enumerate every site that mentions the protocol number in the body (must be exactly one definition).
6. Tests (§13 F2b subset, two real servers in one process): with peering + edge → relayed, acked, `delivered_at` only on the peer's ack; reply from the remote agent arrives with the FQ `from`; peering down → row queues, delivers on reconnect, no duplicate at the remote (dedupe); `ttl_ms=0` with the peering down → dropped, up → relayed; a 601-row backlog after an outage drains fully with ZERO `RATE_LIMITED` (bucket + cap), and a forced `RATE_LIMITED` leaves the row pending AND halves the refill until the next success; an over-stated local `rate_per_min` converges rather than loops; `ACK_TIMEOUT`/`CONNECTION_RESET` leave rows pending and back off; remote `RELAY_REFUSED` → `failed_code` + `expires_at`, `countPendingMessages` excludes it, `REMOTE_REFUSED` reaches the live sender; `AUTH_FAILED` after receiver-side revocation stops the forwarder (no reconnect loop — assert the reconnect count stays 0 over a window); `PATCH {token}` restarts the forwarder and queued rows survive; THE REQUIRED TEST above. Every absence with a positive control; every mutant semantic, not structural (failing test names must relate to the property).
